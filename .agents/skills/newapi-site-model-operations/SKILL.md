# New API 站点与模型操作指南

本指南用于直接执行用户明确要求的 New API 线上管理操作。国内站与国际站的后台对象和操作逻辑相通；不要因站点是国内或国际就重复探索不同流程。差别只体现在站点实例、货币/价格口径、供应商实际可用模型与站点版本能力。

常规操作先读取并遵循 [API 合同速查](references/api-contracts.md)。该速查已经固化了本项目的路由、对象边界、核心字段、定价请求结构和回读顺序；执行普通增删改查时不要重新搜索代码库。仅当线上接口返回 404、字段校验失败、响应结构不同，或用户明确指定了不同版本时，才针对不一致点核对代码或线上文档，并把确认到的差异作为本次任务事实。

## 操作前收集的信息

开始前确认以下信息。上下文中已经明确且仍适用于本次任务的项目可以复用，不要反复索取；缺少关键项时先向用户询问，不猜测。

- 目标站点的完整 URL，并确认本次操作是国内站、国际站还是两者。
- 该站点有管理权限的访问令牌。令牌应通过安全的现有凭据机制使用；不要写入文档、命令历史、日志、代码、截图或最终答复。不要复用其他站点的令牌。
- 操作范围：基础设置、增加/修改供应商、增加/修改模型、定价，及任何明确排除项。
- 供应商操作所需信息：供应商显示名称、渠道类型/协议、API 根地址、上游凭据、支持的模型 ID、必要的附加参数（例如组织、区域、版本、部署名）。上游密钥仅用于获授权的站点配置，不回显。
- 模型操作所需信息：站点公开模型 ID、上游真实模型 ID、应挂载的供应商/渠道、模型能力和端点、描述、中文标签、可用用户组，以及是否需要模型映射。
- 定价所需信息：币种（国内站通常 RMB，国际站通常 USD，但以用户要求和站点配置为准）、计价单位、输入/输出价、缓存读写价或折扣、上下文/时段/阶梯规则、固定请求价或按图片/秒数等用量价格。用户未给出的价格或规则不可自行编造。
- 涉及基础配置时，确认要改的具体设置、目标值和影响范围；“基础配置”不是授权全面调整站点。

如果用户已经在本轮或有效上下文中提供了这些信息，不要重复询问。执行前可简洁列出将修改的对象和价格口径；范围不清或关键信息缺失时暂停写操作。

## 通用操作约束

1. 只使用用户指定的站点和凭据。国内/国际站必须分别读取、分别修改、分别验证；不能把一个站点的配置当成另一个站点已同步。
2. 先读取线上当前配置并确认站点版本、管理 API 能力和现有对象。仓库本地路由或旧对话只能作为线索，不能证明线上版本提供相同接口。优先使用站点实际管理界面或其当前 API；遇到接口不存在、字段语义不明或版本不匹配时停止并报告，不要连续尝试猜测性的写接口。
3. 写入前确定目标对象的唯一标识和变更前值；只做用户要求的最小修改。避免重复创建供应商、重复模型条目、覆盖其他渠道映射、重置整张价格表或批量清理无关数据。
4. 将“渠道可调用”“站点模型目录可见”“模型说明/标签”“计费价格”视为相互关联但独立的配置。完成后分别回读核验，不能以模型出现在列表中推断渠道和计费都正确。
5. 不把令牌或 API Key 放入最终答复。不得为验证而输出凭据；可以报告已配置/已测试及脱敏后的对象信息。
6. 失败、响应与预期不符、配置写入后无法回读或无法判定影响范围时停止后续修改，说明已完成和未完成部分。未经授权不删除渠道/模型、不停用现有服务、不改反向代理或服务器。

## 快速执行模式

对用户已经明确给出站点、令牌、供应商、模型和价格的任务，按以下固定顺序执行，不重新设计流程：

1. 从 `references/api-contracts.md` 选择对象和端点，读取目标对象现状。
2. 计算或整理只涉及目标对象的变更；保留未提及字段和既有映射。
3. 按 Vendor → Channel → Model → Pricing 的依赖顺序写入，未要求的对象跳过。
4. 每一步写入后立即回读；任何一步不一致就停止，不继续扩大变更范围。
5. 按站点分别汇报对象 ID、模型 ID、非敏感配置、价格单位和验证结果，绝不回显凭据。

## 1. 站点基础操作和配置

“基础操作和配置”必须落实为具体对象与目标值，例如站点名称、用户注册、默认分组、公告或某一明确选项。不要把模糊请求解释成全面巡检或优化。

- 先读取目标设置的当前值、可选值、依赖项和可能影响的用户/渠道。
- 确认目标值及单位/作用范围；对会影响注册、鉴权、计费、用户可见性或全站请求的设置，写入前明确告知预期影响，并仅在用户要求范围内执行。
- 使用该站点当前支持的管理界面或 API 修改单项配置。不要直接改数据库，除非用户明确要求且不存在适用管理接口，并已核对影响。
- 写入后重新读取配置；需要时用低风险、无真实消费的方式验证行为。验证可能产生费用、改变用户数据或触发上游任务时，先征得用户明确授权。

## 2. 添加或整理供应商

供应商（Vendor 元数据）与供应商渠道（Channel，含端点和凭据）不是同一对象。根据用户要求判断需要创建哪一个，不要认为新增 Vendor 就已接入上游。

- 添加前分别查找 Vendor 名称/别名和已有渠道端点。相同供应商的多个端点或按模型拆分的渠道，应遵循用户确认的统一名称；不要仅凭名字相似或域名相似自行合并不同上游。
- 已有 Vendor：复用其元数据，仅当用户要求时调整名称、图标或链接等信息。
- 新 Vendor：按站点要求补齐显示名称和必要展示元数据，避免创建重复项。
- 新渠道：确认渠道类型/协议、Base URL、API Key、模型 ID、模型映射、分组/优先级/状态及所需协议参数。创建前保留现有渠道配置，不复制不适用于新渠道的密钥、ID、映射或折扣。
- 不因渠道创建成功就宣称模型已经完成接入。用站点支持的渠道测试或低风险请求确认连通性；如测试会消耗上游额度，应在用户已授权的任务范围内控制测试。
- 写入后回读供应商与渠道，确认名称、端点、模型清单、映射和状态符合预期；密钥字段只核验是否配置，不读取或展示明文。

## 3. 添加模型

先确定这次是“向已有供应商/渠道增加模型”还是“增加新供应商并接入模型”。用户提到的模型 ID 可能是站点公开 ID，也可能是上游 ID；二者不同则设置明确映射，不能擅自改成近似名称。

### 使用已有供应商/渠道

- 找到真实承载该上游的渠道，核对渠道类型、Base URL、当前状态、既有模型和映射。
- 在不破坏原有模型列表和映射的前提下，把上游模型加入正确渠道；必要时单独设置站点 ID → 上游 ID 映射。
- 检查模型别名、协议端点和通用前缀映射，确保不会把其它渠道/模型错误路由到新模型。

### 新供应商并接入模型

- 先按第 2 节识别/创建 Vendor 与渠道，再按渠道协议增加模型；新建渠道和模型配置应尽量在可验证的小步骤中完成。
- 供应商的上游模型列表不等于站点的模型目录。需要用户前台展示时，另行创建或更新模型目录元数据；只有渠道路由需求时不要擅自增加面向用户的模型。

### 模型目录信息

按用户要求维护模型显示名称、中文描述、标签、能力/端点、价格展示及可用组。除非用户指定语言，结合站点既有约定；不要把供应商模型 ID、目录条目和定价对象混为一个对象。

完成后分别核对：站点模型 ID 是否可见、映射后的上游 ID 是否准确、预期渠道是否启用且包含该模型、描述/标签/能力是否正确，以及价格是否单独配置。必要时做一次经过授权的调用测试。

## 4. 调整模型价格

价格配置属于计费变更。先核对用户给出的价格单位、币种、输入/输出含义、缓存规则和计费模式，再读取目标站点当前价格与倍率；若站点已有非默认或复杂规则，修改前保留并比较，不能静默覆盖。

- 用户价格若为 USD 或 RMB 每百万 token，应明确记录单位为“每 1M token”；缓存命中、缓存写入若有价格，按用户给出的官方口径单独设置。用户指定“按官方价的某折”时，应确认折数作用于哪些 token 类型，不自行假定缓存读写也使用同一倍率。
- 仅当确认目标模型使用传统 token 倍率模型，且目标实例的 `QuotaPerUnit` 和价格换算语义已验证时，才可用倍率换算。此仓库当前实现中，USD 输入价/1M 与 `ModelRatio` 的关系为 `ModelRatio = 输入价 × QuotaPerUnit / 1,000,000`；在 `QuotaPerUnit=500000` 时等于输入价的一半，`CompletionRatio = 输出价 / 输入价`。不要将该示例套用到不同 `QuotaPerUnit`、RMB 转换、特殊倍率、固定价或新版价格方案。优先使用线上价格配置提供的预览/换算能力并核验其结果。
- 若输入价为 0 而输出价非 0、出现负值/非有限值、比率无法表示、价格方案有上下文/时段阶梯，或模型按次/图片/音频/视频秒数计费，不要硬塞进普通输入/输出 token 倍率；使用站点支持的对应计费模式，或暂停并说明缺少的配置依据。
- 图像、视频、音频、任务型模型可能按请求数、张数、时长、分辨率、质量、缓存或上游动态用量计费。必须按用户给定单位配置，不能因为渠道按次数扣款就把站点也设成按次；也不能默认所有视频都是 token 计费。
- 执行前复述一行核对：站点、模型、币种、输入/输出及缓存单价或折扣、计费单位。一次仅修改目标模型；如果模型跨渠道共享计价，先确认站点是否按公开模型 ID 全局计价及其影响范围。
- 写入后重新读取生效价格，检查精度、倍率和缓存价格；利用站点预览或小额/零风险计算样例验证最终展示/扣费口径。未经用户明确许可，不做真实付费调用。

## 完成汇报

按站点分别报告成功、部分完成或失败；列出更改对象、关键非敏感字段、价格币种/单位、回读验证和未解决项。不要在文档或答复中复述访问令牌、API Key 或历史会话中的凭据。
